GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、作業がローカルでリアルタイムに行われるため、ツールの呼び出しやファイル編集を逐次確認できます。各差分をインラインでレビューし、変更ごとに承認または元に戻し、エディターを離れずに追加のプロンプトで会話を誘導して、作業を修正・拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッション中にエージェントを誘導し、ハイコントラスト モードに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントは、ハイコントラスト モードを実装しています。作業中にデザイン チームから追加のリクエストがありました。既定のテーマを暗すぎると感じるユーザーのために、ライト モードの切り替えも追加してほしいとのことです。新しい会話を始めるのではなく、既存のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する手順 (調査するファイル、実行するコマンド、提案する編集) が表示されます。ファイルを編集すると、差分と **Keep** / **Undo** ボタンがチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールしてツールの実行状況を確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
    - **Keep** を選択すると、変更を承認します。
    - **Undo** を選択すると、変更を元に戻して、エージェントにもう一度試させます。
4. チャット上部の **Files changed** 表示を開くと、このセッションでエージェントが変更した作業セット全体を確認できます。

> [!NOTE]
> ツールの実行 (ターミナル コマンドなど) に許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可するコマンドは慎重に選んでください。

5. エージェントがハイコントラスト モードの実装を終えるまで待ちます。最後に、変更内容の要約が表示されます。

## エージェントにライト モードを追加するよう指示する

ハイコントラスト モードができたので、同じ会話を続け、ライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントは以前の作業から、変更したコンポーネント、スタイルの方針、設定した local storage の使い方などのコンテキストを保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前回の変更を確認しながら作業を続け、ライト モードの追加を提案します。
3. ハイコントラスト モードと同じように、新しい編集をレビューし、差分ごとに **Keep** または **Undo** を使います。
4. エージェントが意図しない方向に進んだ場合 (たとえば、好まない方法で切り替え UI をリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送信します。

> [!TIP]
> 進行中のセッションを誘導すると、最初からやり直すより効率的です。追加プロンプトで調整を依頼できます。たとえば、「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」、「切り替えを 3 つに増やさず、既存の設定パネルにライト モードを追加する」、「両方の切り替えにキーボード ショートカットも追加する」などです。

## 作業セットをレビューする

変更をコミットする前に、エージェントが変更した内容を簡単に確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルをすべて確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開いて差分を確認します。カスタムエージェントからのアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による保持など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、進行中のセッションを監視し、誘導しました。ファイル編集ごとに確認し、変更を承認または拒否して、コンテキストを保ったまま追加プロンプトで作業を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- ファイル編集を個別に承認または拒否しました。
- 追加プロンプトで作業中のセッションを誘導しました。
